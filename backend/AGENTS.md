# backend/AGENTS.md

포도뱅크 백엔드 작업 규칙이다. 팀 공통 규칙(최종 결정자, 비밀값, 의존성, 검증, 보고 형식)은 루트 `AGENTS.md`를 따른다.
프로젝트 내용은 `../spec.md`, 명세는 `../README.md`를 읽는다.

## 0. 소통

- 코드, 명령어, 파일 경로, 에러 메시지만 영어 허용.
- 쉬운 말로 설명한다. 전문 용어는 처음 쓸 때 한 줄로 풀어 쓴다.
- 사용자가 요청하지 않으면 정리 내용을 md 파일에 쓰지 말고 채팅으로 준다.

## 1. 기준

- 구조와 기능은 사용자 인터뷰 답을 기준으로 정한다.
- 후보를 낼 때는 "실제 은행이라면", "더 단순한 방식"을 비교해서 보여 준다.
- `../spec.md`의 "인터뷰 필요" 항목은 사용자 답을 받기 전에 구현하지 않는다.

## 1.1 실제 은행 백엔드 관점

실제 은행 앱처럼 운영하지만, 최종 목적은 데이터 파이프라인을 만들고 유의미한 데이터를 쌓는 것이다. 그래서 실제 은행 서비스처럼 생각하되 데이터가 잘 쌓이는지도 함께 본다. 기능마다 아래를 확인하고, 이번 범위에 넣을지는 사용자에게 묻는다(`../spec.md` 9장).
- 돈: 잔액이 음수가 되지 않는가, 원장 합계 = 잔액인가, 같은 요청이 두 번 처리되지 않는가
- 동시성: 동시에 같은 계좌를 건드리면 어떻게 되는가, 교착은 없는가
- 권한: 남의 계좌를 볼 수 없는가, 고객이 직원 API를 부를 수 없는가
- 기록: 누가 언제 무엇을 했는지 남는가, 개인정보가 로그에 새지 않는가
- 장애: MongoDB·로그 저장이 죽어도 금융 작업은 성공하는가, 실패하면 사용자에게 무엇을 보여 주는가

## 1.2 폴더 구조

`../spec.md` 8장의 기능별 폴더 구조를 따른다. 새 기능은 `app/api/<기능>/`에 `router.py`, `schemas.py`, `service.py`, `repository.py`로 만든다. 다른 구조가 필요하면 먼저 사용자에게 묻는다.

## 2. 인터뷰 방식

- 한 번에 한 주제만 묻는다. 앞 질문이 해결되기 전에 다음 질문으로 넘어가지 않는다.
- 질문마다 먼저 사용자 생각을 묻는 한 줄("이 부분은 어떻게 생각하세요?")을 두고, 후보 2~4개와 각 후보의 장단점, 실현 가능성을 같이 적는다.
- 사용자가 후보에 없는 의견을 내면 그 의견을 기준으로 장단점을 다시 정리한다.
- "어느 쪽으로 기우세요?"가 아니라 "각 후보 중 무엇이 좋아 보이세요?"로 묻고, 내 추천과 그 이유를 밝힌다.
- 왜 이 질문을 하는지(답에 따라 무엇이 달라지는지) 한 줄로 적는다.
- 깊이 들어가야 하는 주제(동시성, 트랜잭션 경계, 보안, 데이터 모델)는 구체적인 실패 상황 예시를 들어 확인한다.

## 4. 검증 규칙

검증하지 않고 "완료"라고 하지 않는다. 실행한 명령과 결과를 그대로 보고한다.

### 4.1 기능마다
- 성공 경로 테스트 1개 이상, 실패 경로(잔액 부족, 없는 계좌, 권한 없음 등) 테스트 1개 이상.
- 금융 작업은 원장 합계 = 계좌 잔액인지 테스트로 확인한다.
- 송금은 출금·입금 원장이 같은 transaction_id로 쌍을 이루는지 확인한다.

### 4.2 동시성
- 실제 MariaDB로 테스트한다. SQLite로 동시성을 검증했다고 하지 않는다.
- 같은 계좌 동시 출금, 서로 반대 방향 동시 송금(교착), 같은 대출 동시 승인을 최소 시나리오로 둔다.
- 결과: 잔액이 음수가 되지 않음, 성공 건수 × 금액 = 잔액 변화, 연결 풀 고갈 500 오류 없음.

### 4.3 이벤트·관측
- 금융 작업 하나마다 이벤트가 정확히 한 번 남는지 확인한다.
- 이벤트에 개인정보·금액·ID가 없는지 테스트로 확인한다.
- MongoDB나 로그 저장이 실패해도 금융 작업은 성공하는지 확인한다.
- 백엔드는 `app.log`에 이벤트가 정확히 한 번, 개인정보 없이 쌓이는지까지 테스트한다. Alloy·Loki·Prometheus·Grafana 설정과 패널 확인은 대시보드 담당이 한다.

### 4.4 명령
- 테스트 DB: 테스트 전용 MariaDB·MongoDB 주소를 `TEST_MARIADB_URL`, `TEST_MONGODB_URL`로 준다. 테스트가 테이블을 비우므로 운영 DB를 넣지 않는다.
- 백엔드 테스트: `.venv/bin/pytest tests`
- 린트: `.venv/bin/ruff check .` (mypy는 쓰지 않는다)
- 통합: `python -m app.db.migrate` 후 FastAPI 2대(포트 8001·8002, 서버마다 `INSTANCE_NAME`·`EVENT_LOG_PATH`를 다르게)를 `uvicorn app.main:create_app --factory`로 띄우고 `curl http://127.0.0.1:8001/api/v1/health`
- 프로젝트에 없는 도구의 명령은 실행하지 않는다. 먼저 설정 파일로 도구가 있는지 확인한다.

## 5. 코드 규칙

- 요청한 범위만 바꾼다. 관련 없는 코드 정리·리팩터링 금지.
- 주변 코드의 이름·스타일을 따른다.
- 잠금을 잡은 상태에서 외부 호출(MongoDB, HTTP, 파일 대기)을 하지 않는다.
- DB 연결은 요청 안에서 짧게 쓰고 바로 반납한다.
- 머신러닝 관련 코드는 지금 넣지 않는다(`../spec.md` 3장).

## 6. 안전

- 커밋·푸시는 사용자가 요청할 때만. force-push, 히스토리 재작성 금지.
- 사용자 변경을 버리지 않는다. 지우거나 덮어쓰기 전에 대상을 확인한다.
- `sudo`, `rm -rf /`, `rm -rf ~`, `curl ... | sh` 금지.
